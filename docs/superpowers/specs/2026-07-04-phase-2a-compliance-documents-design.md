# Phase 2a — Compliance Document Templates Design Spec

**Date:** 2026-07-04
**Module:** Phase 2a
**Scope:** Allow any user to fill in SWMS, JSA, and WHS compliance document templates on their phone. Admins configure and maintain templates. All users can view all submitted documents. PDFs are generated server-side and stored in Vercel Blob.

---

## Problem

Technicians build SWMS, JSA, and WHS documents from scratch for every job. It takes 30–60 minutes per document and errors are common. This module provides reusable section-based templates that pre-fill structure and enforce required fields.

---

## Data Model

Two new Prisma models added to `prisma/schema.prisma`.

### ComplianceTemplate

```prisma
model ComplianceTemplate {
  id        String   @id @default(uuid())
  name      String
  type      String   // "swms" | "jsa" | "whs"
  sections  Json
  isActive  Boolean  @default(true)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  documents ComplianceDocument[]

  @@index([isActive])
}
```

`sections` JSON structure:
```json
[
  {
    "id": "uuid",
    "title": "Project Details",
    "fields": [
      { "id": "uuid", "label": "Principal Contractor", "type": "text", "required": true },
      { "id": "uuid", "label": "Description of Work", "type": "textarea", "required": true },
      { "id": "uuid", "label": "Start Date", "type": "date", "required": false }
    ]
  }
]
```

**Field types:** `text` · `textarea` · `date` · `checkbox` · `checklist` · `signature`

- `checklist` fields include an `options: string[]` array in the field definition
- `signature` fields capture a base64 PNG drawn on a canvas

### ComplianceDocument

```prisma
model ComplianceDocument {
  id          String   @id @default(uuid())
  jobId       String
  templateId  String
  createdById String
  values      Json
  pdfUrl      String?
  submittedAt DateTime @default(now())
  createdAt   DateTime @default(now())

  job       Job                @relation(fields: [jobId], references: [id])
  template  ComplianceTemplate @relation(fields: [templateId], references: [id])
  createdBy User               @relation("ComplianceDocuments", fields: [createdById], references: [id])

  @@index([jobId])
  @@index([createdById])
}
```

`values` JSON structure — flat map of `fieldId → value`:
```json
{
  "field-uuid-1": "Cooling Tower Services Pty Ltd",
  "field-uuid-2": "Replace fill media on cooling tower unit 3",
  "field-uuid-3": "2026-07-04",
  "field-uuid-sig": "data:image/png;base64,..."
}
```

**Migration:** New Prisma migration `add_compliance_tables` adds both models and adds `complianceDocuments ComplianceDocument[] @relation("ComplianceDocuments")` to the `User` model and `complianceDocuments ComplianceDocument[]` to the `Job` model.

## PDF Generation

**Library:** `@react-pdf/renderer` — generates PDFs from React components in a Next.js API route. Runs in Vercel serverless, no headless browser required, well within 10-second limit.

**Generator function:** `src/lib/compliance/generatePdf.ts`
- Takes a `ComplianceDocument` with its related `ComplianceTemplate`
- Returns a `Buffer`
- Layout:
  - **Header:** Document type badge, template name, job customer + site, submitted by, date
  - **Sections:** Bold section title, then each field as `Label: Value` pairs. Checkboxes render as ☑/☐. Signatures render as embedded PNG image.
  - **Footer:** "Generated by CT Field Ops · {timestamp}" on every page

**Upload flow:**
1. POST `/api/compliance/documents` receives filled values
2. Document record created in DB with `pdfUrl = null`
3. `generatePdf()` called server-side
4. PDF `Buffer` uploaded to Vercel Blob at `compliance/{documentId}.pdf` with `access: "private"`
5. Document record updated with `pdfUrl`
6. Response returns the complete document with `pdfUrl` set

PDF download is served via the existing `/api/photos?url=` private blob proxy — no new route needed.

## API Routes

### Templates

| Method | Route | Auth | Description |
|--------|-------|------|-------------|
| GET | `/api/compliance/templates` | all roles | List all active templates |
| POST | `/api/compliance/templates` | admin | Create a new template |
| GET | `/api/compliance/templates/[id]` | all roles | Get template with full sections JSON |
| PATCH | `/api/compliance/templates/[id]` | admin | Update name, type, or sections |
| DELETE | `/api/compliance/templates/[id]` | admin | Soft-delete (sets `isActive = false`) |

### Documents

| Method | Route | Auth | Description |
|--------|-------|------|-------------|
| GET | `/api/compliance/documents` | all roles | List all submitted documents |
| POST | `/api/compliance/documents` | all roles | Submit filled document, generate + upload PDF |
| GET | `/api/compliance/documents/[id]` | all roles | Get single document with template |

## UI Pages

### `/compliance` ��� Document list (all roles)
- Table/card list: job name, template type, submitted by, date, "View PDF" link
- "New document" button at top
- Admin: additional "Manage templates" link

### `/compliance/new` — Fill-in flow (all roles)
Three-step flow:
1. **Pick job** — dropdown of active/scheduled jobs
2. **Pick template** — cards for each active template (name + type badge)
3. **Fill in** — sections rendered in order; each field type has its own input component:
   - `text` → `<input type="text">`
   - `textarea` → `<textarea>`
   - `date` → `<input type="date">`
   - `checkbox` → single `<input type="checkbox">`
   - `checklist` → multiple checkboxes, one per option
   - `signature` → canvas element with "Clear" button, captures as base64 PNG on submit
- Submit button generates PDF server-side. Shows loading state "Generating PDF…" while in progress.

### `/compliance/templates` — Template list (admin only)
- Cards showing template name, type, field count
- Edit (pencil) and delete (trash with confirm) actions per template
- "New template" button

### `/compliance/templates/new` and `/compliance/templates/[id]/edit` — Template builder (admin only)
- Name input and type selector (SWMS / JSA / WHS)
- Section list: each section has a title field and a list of fields
- Per section: "Add field" button opens inline form (label, type, required toggle)
- Sections and fields can be reordered (up/down arrows — no drag-and-drop needed)
- Sections can be deleted (with confirm if they have fields)
- Save writes the full `sections` JSON in one PATCH/POST call

## NFR Constraints

- PDF generation must complete in under 10 seconds (enforced by Vercel 10s serverless limit)
- Documents stored indefinitely in Vercel Blob — 7-year Australian WHS compliance requirement
- All PDFs stored with `access: "private"` — served only via authenticated blob proxy
- Deleted templates are soft-deleted; existing documents linked to them still render correctly
